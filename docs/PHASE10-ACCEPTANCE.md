## 隐私与资源控制

密码、验证码、邮箱会话和令牌仅在内存；关闭应用需重新登录，退出/过期清除创作权益。认证 SDK 不自动创建网络会话、不从 URL 获取 token、不把凭据写入 SQLite/localStorage；只在主动账号操作时使用固定 HTTPS origin，并禁用请求重定向、Cookie 和 Referer。为 WebView 101 使用 AbortController 超时，避免依赖其未实现的 AbortSignal.timeout。

照片、原图、照片名称、相册关系、标签、收藏、分享文案和创作图片不进入账号 API；原图仍在本机。Canvas 重新编码 JPEG 不携带原图 EXIF/GPS；取消或进入后台会释放正在处理的原图与成品预览。自建相册保存不会无故销毁同组选片的成品。

原生分享只写 `Cache/nobi-share` 中生成的成品；Android FileProvider 仅开放该目录，已移除默认外部存储与整个缓存目录范围。没有新增照片写入、麦克风、位置或音乐库权限。分享成功选择目标后，副本需保留供目标应用读取，超过 24 小时后于后续前台清理；未启动时不会后台定时清除。取消或失败删除本次副本，不删除用户照片。iOS 已申报可选账号的邮箱/用户 ID 用途，以及文件时间戳 API 的 C617.1 理由。

## 上海服务器实际结果

- 使用既有 `nobi-photos-cloud-db` 的独立 `nobi_photos_cloud`，先备份再新增低权限 `nobi_photos_auth` 与 `auth` schema；旧业务角色不能读取认证 schema，认证角色不能读取旧业务 schema。没有连接其他项目的数据库或生产数据库。
- 官方 Supabase GoTrue 2.196.0，镜像固定摘要 `c0c25187a6b835e65a6f6e6c6b39d090e832d40e6de5186f2c038e0411944232`；网关仅运行缓存官方镜像内 Node 22.23.2，覆盖 entrypoint 与健康检查，不启动 Studio。网关基础镜像摘要 `94a2a9d2906e8b4109e55159a62e241c3044709a492913ea8edd34b14973d288`。
- 两个服务独立资源上限 160MiB/0.30 CPU 与 96MiB/0.20 CPU，仅发布 `127.0.0.1:15433`；数据库继续 `127.0.0.1:15432`。采样占用约 36.7MiB 与 20.96MiB，不代表负载容量承诺。
- 真实 Auth/数据库验证注册、验证码、未验证登录拒绝、已验证密码登录、错误密码拒绝、密码恢复、权益查询、伪造 token 拒绝、照片载荷拒绝、外部 user id 删除拒绝、本人注销和注销后访问拒绝均通过。服务重启后再次通过，临时测试账号清除。
- 测试邮件只进入内网接收器，收件地址只允许 `example.invalid`，未发送真实邮件。密钥在服务器生成并保存在受限文件，不输出或入库。备份在认证初始化前后各执行，并检查 dump 可读；完整恢复演练尚未完成。
- 已新增专用 HTTP 站点，本机带相同 Host 的 ACME 文件可读；公网连接到正确 IP 后却收到 302 至 `https://dnspod.qcloud.com/static/webblock.html?d=photos.nobistudio.com`。证书机构跟随此跳转后认证失败。**HTTP 站点尚未切成 HTTPS，续期 hook 也尚未安装；账号 API 的公网开关保持 false。** 不将该状态称为 HTTPS 已部署成功。

这是官方 Supabase Auth 加本应用受限权益/注销网关，不是另起完整 Supabase Studio、Storage、Realtime 或通用 PostgREST。完整 Supabase 项目的替代接入 SQL/Edge Function 保存在 [账号部署说明](../deploy/account/README.md)，不能与当前网关授权实现混用。
